# Supported Languages

CodeGraph extracts code structure deterministically using tree-sitter grammars and custom
embedded extractors. No AI, vectors, or embeddings are involved. The output is byte-stable
across runs.

**38 code and template language IDs** are supported, grouped into three extraction tiers.
Three additional Godot project/resource format IDs are tracked for file/framework
analysis. Internally this is 41 concrete IDs plus the `unknown` fallback (42 entries in
`LANGUAGE_STRINGS`).

> **Note on TypeScript/JavaScript variants:** `typescript` and `tsx`, and `javascript` and
> `jsx`, are distinct grammar variants internally (separate `Language` enum entries). They
> share grammars but handle different file-extension sets. The table lists each variant
> separately so the extension mapping is unambiguous.

---

## Tier 1 — Full symbol extraction (29 languages)

Tree-sitter parses the file and extracts all symbols (functions, classes, structs, methods,
variables, imports, etc.) plus call and dependency edges. This is the richest extraction
level. Grammar error nodes are common and tolerated when useful symbols survive. If the
parse tree has errors and collapses to only the synthetic file node, indexing still succeeds
but emits and stores `parse produced no symbols (tree has errors)` so an empty graph is never
presented as a clean parse.

A read through a type, a static member or an enum value (`JsonScope.EMPTY_DOCUMENT`,
`Color::RED`), references the type it reads through in Java, C#, Kotlin, Swift, Scala, Dart,
PHP and C++, and a Rust variant path (`Mode::A`, `mode::Mode::B`, a `Mode::C(x)` pattern,
`Self::A` in an impl) the enum that declares the variant, nothing else: a Rust associated
const read the same way (`Limits::MAX`) references no type. The receiver must be one
capitalized name, and an access that a call is made through stays the call's. tree-sitter-cpp writes every C++
scope as a namespace name, so a capitalized scope (`Color::RED`, `Limits::kMax`) is read as the
type it names; a lowercase namespace (`std::`) and a global-scope read (`::g`) name none. A symbol also
references the constants and variables of its own file that it reads (value references, see
[`data-model.md`](data-model.md#edges)).

PHP, Pascal and CFML names ignore case: a reference written in another case than its
declaration (`formatprice()` for `FormatPrice`) passes the name pre-filter and is matched by its
name in any case, still only when one node has that name in any case.

In TypeScript, TSX and ArkTS, what a `declare module 'x' { … }` or `declare global { … }`
body declares is exported, as TypeScript's binder exports it: it merges into the module's
or the global scope's type (`interface Window`, a library's `PluginOptionsByType`), so it
is reachable from other files and never dead code. A body holding an export declaration of
its own (`export {…}`, `export =`, `export default x`) exports only what that names; a
namespace nested in an ambient body is ambient too, and `declare namespace X` stays the
file's.

In Python, a call written as a bare name (`get(1)`) never means a method, as Python has no
implicit `self`. It takes another file's function or class only when its own file neither
imports the name from a module outside the project (`from django.shortcuts import render`)
nor binds it itself (`view = UserView.as_view()`, a parameter), unless that symbol is a
pytest fixture the test can take by name. A call through a receiver the graph keeps no type
for (`User.objects.get()`, `self.client.login()`) means only a method of a class the
chain's last link names (`objects`, `client`; underscores and case aside) or a function or
class of a module of that name. In every language but C and C++, a function or type
declared inside a function, or a method of such a type, is in scope only in that function.

A Python name imported from a package (`from users.models import User`), or used through
an imported module (`generic.ObjectEditView`), is the module's own top-level definition,
else the one it re-exports by name (`from .tokens import Token`) or through a star import
(`from .users import *`), up to three modules deep. Two imports rebinding the name (`try:
from .fast import Parser` / `except ImportError: from .slow import Parser`), or star-imported
modules offering different definitions, bind nothing. A parenthesized from-import binds
every name it lists, one per line or not; a comment or docstring binds none. In a method
value, `pkg.mod.Cls` is the class `import pkg.mod` names, unless another import shares the
module's last segment. A call written on `self` (`self.get_ip(request)`) is the class's own
or inherited method even when the file imports a function of that name.

A method value on a Python module global with no static type (`pool.submit(settings.conn.fetch)`,
where `conn = None` is rebound by `global conn; conn = Store()`) is a method of the classes the
global can hold: what its module assigns it, at module scope or in a function that declares it
`global`, and what other production modules write to it (`settings.conn = Store()`). One class
gives its own method; several give the nearest declaration they all inherit. Any binding that
is not a whole constructor call (a factory, a conditional, a tuple target, `for`, `with`, an
import, a star import, a namespace-dict write, an annotation the value contradicts), a write
whose import could name another module, or the caller binding the name itself, leaves the
value unresolved; a test that installs a double (`settings.conn = MagicMock()`, any test file
or `conftest.py`) sees no production type, and a `__main__` block is script code, not module
state.

A pytest test's parameter is the class its fixture returns (`return Cls(…)`, or a local
assigned `Cls(…)` and returned), so a call on it is that class's method, and none of the
project's when the class comes from outside (click's `CliRunner()`). The fixture is the
test module's own, else the nearest `conftest.py` above the test's, or one a module such a
conftest star-imports or lists in `pytest_plugins` defines. A local bound to a Django
manager call that returns one instance (`site = Site.objects.create(…)`, also `get`,
`first`, `last`, `latest`, `earliest`, `get_by_natural_key`) is that model; `filter` and
`all` return a QuerySet and type nothing. A keyword argument inside a call
(`prefix=IPNetwork(…),`) does not bind the receiver it names.

## Adding custom extension mappings

Non-standard extensions can be mapped to any supported language via `.codegraph/codegraph.json`:

```jsonc
{
  "extensions": {
    ".x": "lua",
    ".blade": "php",
  },
}
```

Keys are dot-stripped and lowercased before matching. Unknown language names are silently
skipped. Exactly one file is read — the resolved project's own `codegraph.json`
under the selected index root; there is no directory-tree walk or cross-project
inheritance.
