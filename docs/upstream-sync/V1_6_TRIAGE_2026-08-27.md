## Recommended implementation waves

### Wave 0 — process safety

1. `838006c`: bounded tree traversal / deep-nesting failure containment.

Required proof:

- an adversarial deeply nested fixture does not abort the process;
- the bad file produces a visible extraction error;
- other files still index;
- ordinary fixture goldens remain byte-identical;
- sync and `index --force` remain byte-identical.

### Wave 1 — graph correctness

1. Erlang arity identity/resolution (`41c1075`).
2. Rust generic impl ownership (`12f7a59`).
3. Rust `self.field.method()` (`7963672`).
4. JS/TS object-literal namespaces (`278a8ed`).
5. TS config inheritance (`474f051`).
6. C++ plain-derived `.h` detection (`d618d94`).
7. Python aliased module imports (#1626).
8. Lua table/function-expression callables (#1616).
9. `.xsjs` / `.xsjslib` import candidates (`a740291`).
10. Watcher live-scope refresh (`cf1b0e3`).

Each extraction/resolution item must grow the relevant byte-stable golden corpus
or add a new documented corpus when none exists. Watcher work must prove a
running watcher removes newly excluded files, admits newly included files, and
does not re-add either from stale queued events.

### Wave 2 — retrieval and large-index behavior

1. Explore path pinning / camelCase / variable seeds (`238dbc5`, `ccb0295`).
2. Exact-name index seek (`9219967`).
3. Ranking-only `deprioritize` (`1d9de88`).

Required proof:

- pinned paths survive tight output budgets;
- unmatched prose containing hyphens is not treated as a file;
- scores/output remain deterministic;
- the exact-name query uses `idx_nodes_lower_name`;
- `deprioritize` changes ranking only, never extraction, graph rows, or direct
  exact-path retrieval.

### Wave 3 — CLI and project discovery

1. Project-local Codex installation (`bc89480`).
2. One-shot bootstrap flags (`0d17dfd`).
3. Exactly-one indexed subproject adoption (`a5c2709`).

The `context` command remains deferred until an external compatibility need is
confirmed.
