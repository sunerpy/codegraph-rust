## Method

The range was read in two passes. Pass A took the 117 commits that change C,
C++, Objective-C, Swift, Pascal, Rust, Dart, VB.NET and Go extraction and
resolution, plus the Go standard-library table script. Pass B took the other
108: JS/TS and JSX, React and the routers, Vue, Express, Python, incremental
sync, general resolution and scan policy, explore and `codegraph context`
output, the installer and upgrade paths, daemon, database and MCP robustness,
and test hygiene. Each commit was read from its message and its source hunks
and compared with the Rust tree. Most rows were probed on the released binary
with a fixture modeled on the upstream test; a sync row was probed by indexing,
editing, syncing, and comparing with a fresh index of the final tree. The probe
names in the evidence column label those scratch fixtures, which were not kept;
each row states its probe's result.

Verification of the classifications:

- Every `ALREADY-HAVE` and `KEEP-RUST` row of pass A was run again with the
  upstream commit's own test fixture. Both `ALREADY-HAVE` rows failed part of
  their upstream test and are `PARTIAL` below; see
  [Corrections during verification](#corrections-during-verification).
- Pass B's ten `ALREADY-HAVE` rows rest on probes of the shapes the row names,
  not on every case of the upstream test. The program that ports this audit
  runs each such commit's new upstream test cases against Rust first; a
  failing case turns the row into `PORT`.

## Open questions for planning

These need a check or a design choice when the rows are planned.

1. **#2683 on Windows** (pass A row 58). Rust compiles the same
   `1UL << FAKE_TRY_BANG` (tree-sitter-swift 0.7.3 `scanner.c:131`) into its
   `*-pc-windows-msvc` builds. The fix is tree-sitter-swift 0.7.4, one of the
   grammar updates dependabot holds in #334, which changes the swift golden.
   It needs a check on Windows.
2. **#2795 on Windows** (pass B row 105). `read_daemon_hello` sets a read
   timeout only on Unix (`crates/codegraph-mcp/src/session.rs:679-682`); a probe
   on Windows decides between `PORT` and `PARTIAL`.
3. **The deferred Rust std gate.** Pass A rows 68, 72, 79, 85, 86 and 88 gate
   calls whose receiver is a standard-library or dependency type. #2715's rule
   (such a type reaches only a project trait impl in scope) covers the narrow
   inferred-std-type gate the owner deferred to the next resolution change.
4. **`codegraph context`** (W9-01). Its contract was frozen against
   `b635dd46`: entry points come from the Rust explore ranking. #2428's wording
   for synthesized hops has to be absorbed; #2785 changes upstream's
   dominant-file ranking, which the frozen contract does not use.
5. **Batches and sync lanes.** Some rows only work together (#2723 with
   #2724; #2542's two halves; #2776 with #2658's local-binding gate; #2567,
   #2568 and #2569 after #2493, #2532 and #2533; pass B row 7 with row 3, row 38
   after rows 37 and 74). Several read text across files and need a sync lane
   or a sync-versus-fresh case: #2533, #2626 to #2628, #2538, #2675, #2684,
   #2615, #2703, #2784, #2757 and #2692 in pass A; pass B rows 10, 24 and 42 hit
   the same 500-per-key name-tail retry ceiling (`queries.rs:1486,1671`,
   SY:2779).
6. **Golden and A/B impact.** #2743 (pass B row 84) likely changes the
   `typescript` golden. Several shapes already reach the right target through a
   weak name match (Go `memSeries` at 0.4, C++ `rocksdb::DB` and `arena_` at
   0.65, Objective-C `_archive` at 0.65); the A/B should count those as
   confidence changes, not new edges.
